## Masalah Utama: TUI Interaktif & Jebakan Batman Path NVM

Sebelum masuk ke baris konfigurasi, kita pahami dulu kenapa menjalankan 9Router di server nggak semudah ketik perintah terus ditinggal tidur. Ada dua kendala utama:

### 1. Mode Default TUI yang Bikin Gagal Otomasi
Kalau kamu jalankan `9router` langsung di terminal, aplikasi bakal masuk ke mode antarmuka teks (TUI) interaktif. Mode ini emang interaktif dan ramah buat pengguna desktop lokal, tapi jadi bencana buat service background (*daemon*) server karena menuntut input keyboard manusia.

Kabar baiknya, 9Router sebenarnya udah nyediain *command line flags* bawaan yang emang didesain buat lingkungan server. Coba cek opsinya:

```bash
9router --help
```

Dari opsi yang tersedia, kombinasi sakti yang kita butuhkan adalah:

```bash
9router --tray --no-browser --skip-update
```

- `--tray`: Menjalankan router di mode background tanpa memunculkan prompt interaktif TUI.
- `--no-browser`: Mencegah server mencoba memanggil browser GUI lokal (karena server kita kan *headless* tanpa layar monitor).
- `--skip-update`: Melewati pengecekan update otomatis saat startup biar booting-nya sat-set dan proses nggak nge-hang kalau koneksi internet pas restart lagi ada latensi.

Saat dites langsung di shell:
```text
⚠ Network-exposed: reachable at http://192.168.1.11:20128 (bound 0.0.0.0).

🚀 9router v0.5.95
Server: http://localhost:20128

💡 Router is now running in system tray. Close this terminal if you want.
```
Web Dashboard tetap aktif di port default `20128`. Tapi begitu terminal kita tutup atau pencet `Ctrl + C`, prosesnya langsung terbunuh. Makanya kita butuh supervisor proses tingkat OS, yaitu `systemd`.

### 2. Jebakan Versi Node pada NVM
Nah, ini *plot twist* teknis yang sering bikin orang kena batunya. Saat kita cek lokasi binary 9Router:

```bash
which 9router
```

Output-nya bakal mirip kayak gini:

```text
/home/efzyn/.nvm/versions/node/v24.19.0/bin/9router
```

Perhatiin path-nya: `/v24.19.0/`. 

Executable 9Router terkunci di dalam subdirektori versi Node tertentu. Kalau path panjang ini kita tulis mentah-mentah ke konfigurasi unit file `systemd`, apa yang bakal terjadi pas bulan depan kamu upgrade Node.js ke versi yang lebih baru (misal dari `v24.19.0` ke `v24.20.0` atau `v26`)? Service systemd kamu bakal langsung **broken alias gagal start** karena direktori lamanya udah nggak relevan atau executable-nya pindah tempat!

## Solusi Elegan: Bikin Script Wrapper NVM

Daripada pusing tiap kali upgrade Node harus ngedit-ngedit file service di `/etc/systemd/system/`, solusi paling *clean* dan *bulletproof* adalah membuat **script wrapper bash sederhana**. 

Script ini tugasnya simpel tapi krusial: memuat environment NVM pengguna secara dinamis, mengaktifkan versi Node default, baru mengeksekusi 9Router. Jadi si `systemd` cukup manggil satu script ini aja tanpa peduli versi Node berapa yang lagi aktif.

Buat file wrapper di home directory kamu:

```bash
nano /home/efzyn/run-9router.sh
```

Lalu paste konfigurasi berikut:

```bash
#!/bin/bash

# Load environment NVM milik user
export NVM_DIR="$HOME/.nvm"
[ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"

# Gunakan versi Node yang diatur sebagai default
nvm use default >/dev/null

# Jalankan 9Router dengan mode server headless
exec 9router --tray --no-browser --skip-update
```

Simpan file (`Ctrl + O`, lalu `Enter`, lalu `Ctrl + X`), lalu jangan lupa beri izin eksekusi (*executable*):

```bash
chmod +x /home/efzyn/run-9router.sh
```

### Pastikan Alias Default NVM Sudah Terarah
Cek alias default NVM kamu dengan perintah:

```bash
nvm alias default
```

Output contoh:
```text
default -> 24 (-> v24.19.0)
```

Sekarang kita tes wrapper-nya secara manual:

```bash
/home/efzyn/run-9router.sh
```

Kalau 9Router jalan mulus dan Web Dashboard di port `20128` bisa dibuka dari browser, tekan `Ctrl + C`. Artinya wrapper kita udah 100% siap diintegrasikan ke `systemd`.

## Membuat Service systemd (Konfigurasi Final)

Sekarang giliran kita serahkan urusan *lifecycle* proses ke `systemd`. Dengan systemd:
1. 9Router bakal nyala otomatis tiap kali server selesai *booting*.
2. Kalau aplikasinya mendadak *crash* atau *out of memory*, systemd bakal langsung me-restart otomatis dalam hitungan 5 detik.

Buat file unit service baru:

```bash
sudo nano /etc/systemd/system/9router.service
```

Isi dengan konfigurasi berikut:

```ini
[Unit]
Description=9Router Headless Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=efzyn
Group=efzyn
WorkingDirectory=/home/efzyn

# Environment dasar
Environment="HOME=/home/efzyn"
Environment="NVM_DIR=/home/efzyn/.nvm"

# Eksekusi wrapper script yang sudah dinamis
ExecStart=/home/efzyn/run-9router.sh

# Fitur auto-heal / auto-restart jika proses down
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

> **Tips:** Sesuaikan nilai `User=efzyn`, `Group=efzyn`, dan direktori `/home/efzyn` dengan nama user non-root yang kamu pakai di server Linux kamu.

### Aktifkan dan Jalankan Service

Reload daemon systemd agar unit baru terdaftar, lalu aktifkan service sekaligus jalankan sekarang juga (*enable --now*):

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now 9router
```

Cek statusnya:

```bash
sudo systemctl status 9router --no-pager
```

Jika berhasil, kamu bakal melihat status hijau cerah yang memanjakan mata:

```text

     Loaded: loaded (/etc/systemd/system/9router.service; enabled; vendor preset: enabled)
     Active: active (running) since Fri 2026-10-02 10:00:00 WIB; 10s ago
```

`enabled` artinya service akan otomatis di-boot saat Linux menyala, dan `active (running)` menandakan prosesnya sudah hidup stabil di background.

## Uji Ketahanan: Test Reboot Server!

Service yang beneran teruji adalah service yang bisa bangkit sendiri setelah server mendadak restart tanpa intervensi manual. Mari kita buktikan:

```bash
sudo reboot
```

Tunggu 1-2 menit sampai server Linux kamu online kembali. Setelah bisa diakses via jaringan, **jangan ketik perintah `9router` apa pun**. Langsung intip statusnya via SSH:

```bash
sudo systemctl status 9router --no-pager
```

Hasilnya? Service langsung menyala rapi dalam kondisi `Active: active (running)`. Buka browser di laptop atau smartphone kamu, akses `http://IP-SERVER:20128`, dan dashboard 9Router langsung siap dipakai. *Effortless!*

## Checklist Saat Maintenance & Update

Biar setup kamu tetap awet dan nggak gampang rusak pas ada pembaruan di masa depan, simpan contekan ini:

### 1. Kalau Cuma Mau Update Package 9Router
Jika kamu hanya mengupdate package 9Router di versi Node yang sama, kamu nggak perlu menyentuh file systemd sama sekali. Cukup update package-nya via npm, lalu restart servicenya:

```bash
sudo systemctl restart 9router
```

### 2. Kalau Kamu Ganti atau Upgrade Versi Node.js di NVM
Ingat konsep dasar NVM: **global npm package terisolasi di masing-masing versi Node**. Jadi kalau kamu install versi Node baru (misal Node 25) dan menjadikannya default:

```bash
nvm install 25
nvm alias default 25
nvm use default
```

Pastikan 9Router juga sudah terpasang di versi Node yang baru tersebut. Cek dengan `which 9router`. Kalau belum ada, tinggal install kembali di environment tersebut (`npm i -g 9router`). Begitu package terpasang, cukup restart servicenya:

```bash
sudo systemctl restart 9router
```

File `/etc/systemd/system/9router.service` tetap aman tanpa perlu diedit ulang!

## Catatan Keamanan: Jangan Buka Port Ini Sembarangan!

Secara bawaan, 9Router mengikat (*bind*) servicenya ke `0.0.0.0:20128`. Artinya:
- Web Dashboard bisa diakses oleh semua perangkat di jaringan lokal (LAN/Wi-Fi rumah).
- **BAHAYA:** Kalau server Linux kamu punya IP publik atau ada pengaturan *port forwarding* langsung di router internet, dashboard kamu berpotensi diintip pihak luar.

**Rekomendasi Keamanan:**
1. **Jangan pernah melakukan port forwarding port 20128 langsung ke internet publik.**
2. Jika butuh akses jarak jauh saat berada di luar rumah, gunakan jaringan privat virtual yang aman seperti **Tailscale**, **WireGuard**, atau **Cloudflare Zero Trust Tunnels**.
3. Jika dashboard hanya ingin diakses secara lokal di dalam server itu sendiri (misalnya jika kamu memasang reverse proxy Nginx dengan autentikasi kata sandi dan HTTPS), tambahkan opsi `--host 127.0.0.1` pada file wrapper `run-9router.sh`.
